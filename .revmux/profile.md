# Профиль проекта

## Что это за софт

`airflow-provider-yandex-admetrica` — Apache Airflow провайдер, публикуемый на PyPI
отдельным дистрибутивом. Он выгружает статистику медийных рекламных кампаний из API
отчётов Яндекс Метрики для медийной рекламы в локальные файлы, откуда DAG забирает их
в S3 и BigQuery.

Это один из семейства независимых провайдеров одного автора: `airflow-provider-avito`,
`airflow-provider-cian`, `airflow-provider-yandex-realty`, `airflow-provider-gmail`,
`airflow-provider-rmq` и другие, лежащие соседними каталогами на уровень выше. Они
задают конвенции этого репозитория: структура пакета (`hooks/`, `operators/`,
`__init__.py` с `get_provider_info()`), `setuptools-scm` с `version_file`, публикация
по тегу через OIDC, `README.md` + `README_RU.md`, `CONTEXT.md` с доменными терминами
и архитектурными швами, `docs/plans/` с планами реализации.

Целевая среда: Airflow 2.x (`>=2.9.1,<3.0`), Python `>=3.10`. Airflow 3 не поддерживается.

## Что здесь чаще всего под ревью

Планы реализации в `docs/plans/*.md` наравне с кодом. План — исполняемый документ:
по нему работает агент или человек, задача за задачей, и ошибка в нём стоит столько же,
сколько ошибка в коде, только обнаруживается позже.

## Что считать настоящим отказом

**В коде:**
- потеря или искажение выгружаемых данных: молчаливо оборванная пагинация, проглоченная
  ошибка API, страница, посчитанная пустой из-за нечитаемого тела ответа
- секрет, покидающий процесс: OAuth-токен в логе таски, в диагностическом событии,
  в тексте исключения, в заголовке или URL, попавшем в лог
- неверная работа с внешним API: параметр, которого нет в спецификации; неверная база
  отсчёта `offset`; лимит, документированный иначе
- поведение, ломающее идемпотентность перезапуска: путь, зависящий от времени запуска
  там, где он должен зависеть только от даты данных
- ошибка, которая проявится только на живом API и молча даст неполные данные

**В плане:**
- шаг, который нельзя выполнить как написано: несуществующий метод, неверное имя
  параметра, ссылка на файл, которого не будет к этому моменту
- задача, использующая то, что появляется только в более поздней задаче
- утверждение о внешнем API, противоречащее его документации
- дизайн, теряющий данные при штатном сценарии эксплуатации
- отсутствие тестов на поведение, которое задача вводит

## Радиус поражения

Провайдер выгружает рекламную статистику в аналитическое хранилище. Неверные или
неполные данные попадают в отчётность и обнаруживаются недели спустя, когда исходный
период уже нельзя перезапросить из-за глубины хранения в API. Молчаливая неполнота
опаснее падения таски: упавшая таска видна сразу.

Утечка OAuth-токена даёт доступ к рекламному кабинету рекламодателя.

Пакет публичный, на PyPI, его ставят себе другие — ошибка в упаковке или в
`get_provider_info()` ломает Airflow у пользователя.

## Планка репортинга

Сообщать о том, что даёт неверные данные, теряет данные, раскрывает секрет или делает
шаг плана невыполнимым.

Не сообщать:
- о стиле формулировок, длине задач и порядке разделов в документации
- об отсутствии UI- и e2e-тестов: в проекте нет UI, e2e-набора не существует
- о поддержке Airflow 3 и Python ниже 3.10 — они вне области
- о размере задач плана как таковом

## Сознательные конвенции — не находки

- **Дублирование кода между провайдерами намеренно.** Это независимые PyPI-пакеты, общей
  библиотеки нет и не планируется. Перенос модуля (например, клиента Loki) из соседнего
  провайдера в этот — принятое решение, а не нарушение DRY. Предложение выделить общий
  пакет находкой не является.
- **Комментарии и документация описывают настоящее, а не историю.** Формулировок вида
  «раньше здесь было», «теперь вместо» в коде и документах не будет; история живёт в
  git. Отсутствие таких пояснений — не пробел.
- **Документация и планы на русском языке**, `README.md` дублируется английской версией.
- **Коммиты без атрибуции ассистента**: трейлеров `Co-Authored-By` и подписей
  «Generated with» здесь нет намеренно.
- **Тесты не ходят в сеть.** `requests` подменяется, `time.sleep` патчится глобальной
  фикстурой. Отсутствие интеграционных тестов против живого API — осознанный выбор.
- **Недокументированное поведение внешнего API** фиксируется как открытый вопрос в
  разделе Post-Completion плана и проверяется на первом боевом прогоне, а не угадывается
  в коде.
